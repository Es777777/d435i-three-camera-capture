# D435i 三机数采工作台 v1.0.0

## 从一个入口开始

1. 完整解压发布包到可写文件夹，双击 **`启动数采.bat`**。当前项目根目录也有同名入口。
2. 第一次自动解压软件专用 Python 3.12、创建独立环境、安装锁定依赖并检查。无需安装 Python、pip、RealSense Viewer 或修改 PATH，无需管理员权限。首次可能需要几分钟，请等待窗口显示“环境已就绪”。
3. 进入工作台，选择“采集与本机标定”“三机标定结算”或“重建 · 合成 · 回放”。以后始终双击同一个入口，环境正常时不会重新安装或联网。

适用 Intel/AMD 64 位 Windows 10/11。当前交付在线包 `D435I_ThreeHost_v1.0.0.zip`，首次需要访问 python.org 和 pypi.org 下载约 220 MB，含软件专用视频编码器，后续无需联网。完整解压后双击统一入口，自动准备运行环境。

工作台会检查依赖、Qt、FFV1 无损视频写入回读、目录写入、配置、相机和输入音频设备。未连接相机或麦克风显示提示，仍可进入离线处理。设备检查只枚举硬件，不开启相机或录音；检测到麦克风不代表已授予录音权限，实际启流在采集窗口完成。

## 采集与处理顺序

每台在采集界面选择不同的 Master / Slave 1 / Slave 2 角色。标定板保持固定，各机完成本机标定后即可直接录像。每段录像包含本机标定快照，每帧绑定时间戳和位姿戳；收集三个 session 并分别重建后，在“三机合成”按对应帧的位姿完成结算和坐标变换。**三机结算文件不再是录像前置条件**。原有“三机标定结算”和加载 rig 功能可选保留。

## 模型对点标定：跟着黄色点点击

沿用之前的 `face_marker_target_blender52_body70_single_mark54` 模型，保持 **70% 尺寸、三面共 15 个凹槽**。正面为 C01–C09；面对模型时，左翼从上到下为 **C12、C11、C10**，右翼为 **C15、C14、C13**。使用原有 5 mm 反光贴，贴在单个 5.4 mm 凹槽中。采集窗口的“模型点位图”可随时查看点号和原模型预览，不需要先连接相机。

1. 开启相机，保持三台相机与模型不动，点击 **“引导标定（模型对点）”**。程序冻结本机 IR1，并放大为独立的对点窗口。
2. 选择画面中能看到的“正面＋左翼”“正面＋右翼”或三面。这里的左右是模型正面的左右，与 Master / Slave 角色无关。
3. 右侧模型图黄色双圈标出当前点。在左侧实拍画面点击对应贴片中心，程序自动吸附附近清晰亮点、标绿并跳到下一点，**不再逐点下拉选号和点击确认**。先选四个正面角点，再选翼面上下两点；看不到可跳过，也可点击模型点号重选、撤销，或重拍清空。
4. **至少 6 个点且含翼面**，通过非共面、贴片朝向和重投影检查后，“检查并保存本机标定”变为绿色，点击即可保存，也可继续补选分散的点。未通过时按钮为灰色，仍可点击查看原因，按钮上方会显示缺少点数或检查失败的原因。保存本机标定后即可录像，无需先做三机结算。

画面标识：**青色圈**是候选亮点，尚未编号；**绿色圈＋点号**是手动确认的对应点；**黄色虚线圈**是在已有点通过检查后计算的下一点预计位置，仍需用户点击核对。相同亮点阵列无法仅凭亮度可靠判断左右和点号，因此不直接自动保存整组对应关系。

滚轮可缩放实拍画面，“适应全图”复位；鼠标悬停显示 4 倍放大和中心十字。没有圈到贴片时可降低“亮点阈值”，也可关闭吸附手动对准中心。原始图像和录像不绘入这些标记。IR1 / IR2 实时预览也可勾选“高亮反光点”，用于调整照明和摆放。

### 出现“重投影误差过大”时

表示实拍点击位置与模型计算位置不一致：RMS 需 ≤1.5 px，每个点需 ≤3 px。最后显示“C11 已确认”只说明最后点击了 C11，并不表示 C11 就是误差最大的点。手动点击偏离贴片中心、点号弄反、贴片中心偏离槽中心或实物几何不符都可能造成偏差；总误差截图不能单独确定原因。

1. 查看右侧按偏差排序的点表，点击“定位最大偏差点”，程序会选中对应编号并放大实拍位置。
2. 核对点号，在实拍贴片中心重新点击。红色点是优先复核对象，橙色虚线是诊断参考，**不要把点击位置直接移到虚线上**。其他已选点会保留。
3. 无法看清的点可以点“移除当前点（可撤销）”，程序会对剩余点重新检查。仍必须至少六点并包含有效翼面；未通过不能保存。只选正面无法通过。
4. 开启吸附时，程序先使用全图亮点，再对点击附近的局部背景计算阈值，帮助定位不够亮的贴片。没有唯一清晰亮点时保留手动位置并提示放大核对；不会按预计位置自动修改点位。
5. 仍无法通过时，点击“导出本次点位与画面”，保存 ZIP。包内有原始冻结 IR1、点击坐标、相机内参和逐点误差，便于复现排查；该包不能作为标定 JSON 使用。

尺寸参数默认沿用原模型：坐标自动乘 0.70，默认反光面内缩 0.55 mm（约 0.75 mm 槽深减 0.2 mm 贴片）。实际贴片厚度不同时展开“尺寸参数”修改；三台应使用一致的实物参数。贴片必须在 IR 中清晰可见，亮度高亮不代表点号或测量精度已验收。

## 录制和处理

每台选择本机麦克风后开启相机。录像同时保存 IR1、IR2、RGB 三路视频、48 kHz 单声道 PCM 音轨、逐帧时间戳、音频 ADC 时间映射和 IMU。v1.0.0 默认“RGB MP4＋红外无损压缩”：RGB 使用 H.264/yuv420p MP4（有损），IR 使用 FFV1 灰度 AVI（逐像素无损）。RGB 可用常见播放器播放；红外科学数据可用支持 FFV1 的播放器或软件处理，也可通过工作台“录像检查／转 MP4”导出播放副本。音轨独立保存在 WAV 中。

可选“三路通用 MP4”进一步减小体积，三路均为有损；红外像素会变化，精密测量需另行验证。原始无压缩和旧 FFV1 模式保留为明确的可选项。录像前自动关闭 emitter；预览时可以切换。音频失败、持续积压或视频流持续中断会停止录像并记录错误。硬件同步继续使用 Master=1、两个 Slave=2。

### 已有 AVI 很大或普通播放器打不开

v8.3 的默认原始格式在 1280×720@30 时，三路约 166 MB/s，12 秒约 2 GB；RGBA/Y800 编码也不被所有播放器支持。文件大小本身不能判断损坏。

在工作台点击 **录像检查／转 MP4**，选择具体 session：

1. “检查保存状态”检查采集报告、帧索引、帧数及首中尾帧；可勾选逐帧完整解码。
2. “导出 MP4 播放副本”生成独立 `mp4_playback_日期_编号` 子目录，逐帧验证转出结果；不覆盖、不删除原视频与索引。不完整采集的警告会保留。
3. MP4 播放副本包含有损转码，不应替代用于精密测量的原始 IR 视频。尚未正常停止、缺少保存报告的录像不允许转出。

### 出现 Disk cannot keep up 或录像一秒就停

v8.2 的三路视频与高频 IMU 共用 96 项队列，并在单线程逐路做 FFV1 编码。编码慢时队列很快溢出，原提示无法区分编码、磁盘和突发排队。v8.3 改为每路视频独立写入、IMU/索引独立队列，并按内存字节限制视频缓存；不降低分辨率、帧率或原始像素精度。

1. v1.0.0 默认选择 **RGB MP4＋红外无损压缩**；压缩率随纹理、噪声和运动变化，没有固定的每分钟大小承诺。原始无压缩仅作可选，在 1280×720、三路各 30 FPS 时约 **10 GB/分钟**。
2. 点击 **测试保存目录录制速度**，在当前所选目录进行三路全分辨率、当前帧率与高频 IMU 的短时写入测试，检查首尾帧像素、计数、积压趋势与排空时间，并强制刷新操作系统写缓存。临时数据自动清理，结果写到 `logs/recording_benchmark_latest.json`。
3. 测速通过后开始录制。三秒短测不能覆盖所有长期负载；实际录像会显示视频缓存占用，并记录逐路写入耗时与峰值。若换目录，需对新目录重新测速。
4. FFV1 模式保留无损压缩，但更依赖 CPU；请先测速。缓存有上限，不用不断增大缓存掩盖长期写入不足。空间少于 512 MB 会停止并排空已接收数据。

每段 `summary.json` 增加 `writer_performance`、错误类别、已接收/已写计数和首个拒绝样本。缓冲超限或写入失败仍将该段标记为不完整，不会静默丢帧并假装成功。`session.json` 保存实际录制模式与各流编码。原本机标定 JSON 可继续加载，升级无需为机位未变化的相机重新点标定。

本机标定有效时“开始录像”可直接点击。按钮旁会说明缺少相机或本机标定等原因。新录像包含 `calibration.json` 和 `pose_stamps.json`；`frames.jsonl` 每帧记录 `pose_stamp_id`、IR1 相机中心在标定板坐标系中的位置、位姿有效性及原有时间戳。位姿戳保存完整位置和朝向，不能仅用三个位置坐标替代刚体变换。坐标原点沿用原模型定义，IR2/RGB 通过保存的设备外参与 IR1 关联。

当前标定位姿按相机与标定板固定使用，各帧可引用同一位姿戳。IMU 检测到机位运动后，原始音视频继续保留，相关帧标记为位姿失效并在合成时排除；没有实时恢复移动机位的位置。后期按帧读取已保存的位姿编号，支持不同帧引用不同已记录的标定位姿，不会把录像开头的位姿套给整段视频。

保存时检查每个 AVI／MP4 的最终帧数与索引，并解码首帧、中间帧和末帧；发现封装失败、编码丢帧或文件不可读会标记录像不完整。日志显示逐文件时长、帧数、大小；summary.json 保留编码、大小及检查范围。抽样回读不等于逐帧完整检查。

录完后进入主窗口的“本机重建 / 三机合成 / 回放”：

1. 本机重建：选择 session，设置人脸 ROI 和反光点阈值，选择新输出目录。IR1/IR2 做被动双目和亮点三角化，RGB 给点云着色。每台可独立处理。
2. 三机合成：把三份 session 和三份本机结果复制到处理电脑，选择三个结果目录；路径改变时填写对应原始 session。自动匹配三条音轨的偏移和漂移；按对应原始帧的位姿戳完成三机标定结算，检查序列号、模型、尺寸、点位和误差，再变换到统一标定板坐标系。无需事先生成或分发 rig 文件。可选两个共同视频事件进一步校正视频时间。共同声音不足、匹配不唯一时拒绝自动合成。
3. 三维回放：旋转、缩放、拖动时间条，查看彩色点云和 Mark 轨迹，可切换平滑与短时补全。当前为点云头部显示，不是完整的蒙皮人头模型；回放窗口不播放声音，对齐 WAV 可单独播放。

合成输出包含 `frames_3d.jsonl`、`clouds/*.npz`、`result.json`、三份 `aligned_audio_*.wav` 和 `sources/camera_*` 中的全部原始视频、音频及日志。三条音轨保持独立，不混成单声道，也不把九路视频重新压成一个视频。原始点位在 `markers`，平滑/短时补点在 `display_markers`，画面不逐点标注“估计”。轨迹 ID 是自动几何编号，尚非人体解剖点号。

输出 `rig_calibrations.json` 保存实际使用的位姿组合及结算结果，每个融合帧记录 `pose_stamp_ids` 与该组合的 `rig_id`。只有一组位姿时同时输出 `rig_calibration.json`。自动录后结算明确记录固定标定板假设，不冒充人工机位布局验收或硬件曝光同步证明。

SDK 不暴露同步线电气连接/锁定状态，不能直接检测所谓 Pin5 是否插好。界面显示角色回读、各流收帧/间隔/缺帧，并可记录同步测试事件；收帧正常不等于线已连接。音频辅助对齐包含声传播与 USB 回调延迟，不能证明 RGB 或 IR 曝光已经锁定。

IMU 从相机启动到关闭持续记录在 `telemetry/`，录像段另存 `imu.csv`。重建保留本机坐标；IMU 触发机位运动报警后，该机后续帧不用于固定外参融合。IMU 不提供可靠位移补偿，也不能证明缓慢位移没有发生。搬迁完整项目时请一并保留 telemetry。

Emitter 关闭后，不存在能保证无纹理皮肤深度准确的算法。此实现使用左右一致性、纹理和重投影检查，丢弃不可靠深度；反光贴片还需要合适的近镜头红外照明才能在两路 IR 中清晰出现。平滑补点不能替代照明、正确标定和实际测量精度。

工作台的“旧版人工标点”保留人工指定同名 Mark 的三机 IR1 后处理。本目录是唯一维护源码。统一入口为 `启动数采.bat`（内部调用 `start.bat`）；旧 `run_capture.bat`、`run_calibration_settlement.bat`、`run_postprocess.bat` 兼容保留，均会先检查并自动准备环境。

## 常见问题

- **第一次下载失败**：连接网络后重新双击入口，或改用完整离线包。保留已解压内容，启动器会复用有效下载。日志可查看 `logs/bootstrap.log`。
- **环境损坏 / 依赖导入失败**：先关闭所有采集和处理窗口，在本目录的终端运行 `start.bat -Repair`；离线包优先从本地重装依赖。原有录像不受影响。
- **只准备环境**：运行 `start.bat -SetupOnly`。严格禁止下载可加 `-Offline`；离线包双击时本来也会优先用随包依赖。
- **相机未发现**：连接 D435i 到 USB 3 接口，关闭占用设备的其他程序，然后在工作台点击“重新检查环境与设备”。系统识别与 USB 驱动问题需要在设备管理器处理。
- **麦克风不可用**：连接输入设备，允许 Windows 桌面应用访问麦克风，并在采集窗口刷新和选择输入设备。
- **重复双击**：同一目录的工作台和各功能会唤起已打开的窗口；环境准备期间再次启动会提示等待。
- **退出工作台**：先关闭其打开的采集和处理窗口，避免中断写盘。采集窗口也提供原有重建入口，录像停止后可使用。
- **迁移到另一台电脑**：使用干净发布包；数据另行复制。移动现有整个目录后，启动器会检查并重新创建失效的虚拟环境，旧环境保留在 `.runtime/backups`。

## 开发与发布

环境准备后运行 `.venv\Scripts\python.exe tools\run_checks.py`，检查在独立进程运行，覆盖录像、结算、重建与工作台。检查使用合成数据，不替代三机实测。

完整离线材料准备好后，可运行 `.venv\Scripts\python.exe tools\verify_bootstrap.py`：在临时中文 / 空格路径中复制干净软件，移除 PATH 中的 Python，验证离线首次准备、重复启动、并发安装保护和损坏运行包拒绝。成功后清理临时环境，报告保存在 `logs/bootstrap_verification.json`。

运行 `.venv\Scripts\python.exe tools\build_release.py` 生成在线小包；增加 `--offline` 准备 Windows x64 的离线依赖并生成离线包。发布只取源码、配置、启动脚本、使用说明和可选离线材料，附文件 SHA256 清单，不包含环境、录像、日志、角色或测试图片。Python 官方运行包地址和摘要见 `tools/runtime.json`。
