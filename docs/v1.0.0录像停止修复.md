# v1.0.0 录像停止修复

基于仓库提交 `d5191d2`。本补丁修复代码中可确认的停止流程与音频状态处理问题；未取得用户现场日志，不能认定所有现场自动停止都由同一个原因造成。

## 修复内容

- 点击“停止录像并保存”立即显示“正在保存”，禁止重复停止和保存期间重录。收到停止请求后，回调停止向录像提交新视频帧和 IMU 样本；预览继续更新。
- 写完缓存、关闭音频及视频解码校验在独立线程执行。采集线程继续处理控制命令和持续 IMU 日志，避免保存时间长时日志队列积满导致相机退出。关闭相机时仍等待保存完成。
- 持续日志每轮最多处理 1000 条或约 10 毫秒，避免生产者不断追加数据使停止命令长时间得不到处理。
- PortAudio 单次输入溢出或状态提示只记录并提示，不再立即结束整段录像。后续音频块和视频继续保存。真实音频写入失败或队列满仍会结束录像。
- 音频中断记录在 `audio_blocks.jsonl` 的逐块状态和 `audio.json` 的 `status_count`、`last_status` 中；最终 `summary.json` 记录 `audio_status`。有音频中断的 session 会保留 `complete=false` 和 `audio_discontinuity`，以免误认为音视频数据全部完整。视频仍会完成写盘及解码校验。
- `summary.json` 新增 `stop_reason`，区分手动停止、相机关闭、采集错误以及写入保护停止。发生异常时日志先给出原因，再执行保存。
- FFmpeg 管道单次写入或关闭输入管道阻塞超过 30 秒会终止卡住的编码进程，释放写入线程并报告不完整；原有进程收尾 120 秒超时保留。该检测覆盖推荐模式和通用 MP4 的 FFmpeg 编码路径，不覆盖旧 OpenCV 编码器或操作系统级存储挂起。

## 使用

### 已安装 v1.0.0

退出采集程序，将“录像修复文件”目录内以下五个文件复制到旧程序中同名文件所在目录，替换原文件：

- `capture_app.py`
- `capture_runtime.py`
- `audio_io.py`
- `recording_io.py`
- `video_encoding.py`

从源码启动时，这些文件在仓库的 `software/` 中；已发布的在线包通常直接位于解压后的程序根目录。五个文件应一起替换。此补丁不修改配置、标定和已有 session。

### 完整包

完整解压 `D435I_ThreeHost_recording_fix.zip`，在 Windows 10/11 Intel/AMD 64 位电脑上双击 `启动数采.bat`。新目录首次启动仍需联网准备原项目依赖。已有标定和保存目录可在界面重新选择。此修复包沿用 v1.0.0 的界面版本号，GitHub 发布标签为 `v1.0.0-recording-fix`。

## 验证结果与边界

本地环境为 macOS ARM64、Python 3.12、PyQt5 5.15.11、OpenCV 5.0.0.93 和 imageio-ffmpeg 0.6.0；RealSense 边界以模拟设备替代，麦克风以合成 PCM 替代。视频编码、文件读写与 Qt 界面使用真实实现。

新增 `software/tests/check_recording_stop.py` 通过：实际停止按钮、慢速保存时继续预览及排空日志、重复停止、保存中拒绝重录、保存后重录、保存中关闭相机、音频溢出后继续录制、正常音频完整性、音频队列满、保存异常、持续日志生产者，以及真实子进程不读输入时的编码超时。

以下五项既有检查在模拟 SDK 导入环境中通过：

- `check_capture_v3.py`
- `check_deferred_capture_v8_2.py`
- `check_recording_integrity_v7.py`
- `check_recording_throughput_v8_3.py`
- `check_video_storage_v8_4.py`

`check_reconstruction_v6.py` 在 RealSense 投影函数对比处无法完成：模拟 SDK 不实现该函数。未将其计为通过，也未修改无关重建代码。既有测试打印的“Windows decoder”等固定文案不代表本次在 Windows 上验证。

真实 D435i、Windows 驱动、USB/硬件同步、实际麦克风及目标电脑上的长时间录像尚需现场验证。可在 Windows 专用环境执行新增检查：

```powershell
$env:PYTHONPATH = (Get-Location).Path
& .\.venv\Scripts\python.exe .\tests\check_recording_stop.py
```

上述命令在含 `capture_app.py` 的程序目录执行，新增检查自身仍使用模拟相机。

现场建议录制一分钟后手动停止，确认三路视频可读、日志出现保存结果、正常音频时 `summary.json` 的 `complete=true`；然后再次录像并重复停止。若仍自动结束，保留该次 session 的 `summary.json`、`audio.json`、编码器日志及界面末尾日志，可据其具体原因定位。

磁盘空间不足 512 MB、视频缓存持续积压、写盘失败及连续 10 秒无视频等原有保护保留。它们意味着当前数据无法继续可靠写入，不能通过简单删除保护来解决。
