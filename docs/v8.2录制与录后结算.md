# v8.2 本机标定后录制，汇总时三机结算

2026-10-18。用户确认相机和标定板在录像期间都固定。本机标定相对同一个固定标定板计算完整位姿，各机可以独立录制；三机标定结算应放在收集和汇总视频时进行。

## 流程

每台选 Master / Slave 1 / Slave 2 中的不同角色，完成或加载本机标定后即可开始录像。不要求先导入另外两机 JSON、生成 rig 或分发结算文件。采集界面直接显示是否具备本机录像条件。重新标定会使旧的可选 rig 失效，但不会阻止使用新本机标定录像。

录完后分别处理本机 IR1/IR2/RGB，再把三个完整 session 与本机重建目录汇总，在三机合成时对齐时间。每个源帧引用自己的位姿戳，用对应的相机到标定板变换进入公共坐标系，并结算该帧使用的三机位姿组合。固定机位的所有帧通常引用同一份本机位姿，不会为每帧制造新的测量结果。

## 保存的数据

- `session.json`：本次采集的标定快照、默认位姿编号、固定标定板约定、位姿文件名及采集元数据。不要求存在 `rig_calibration` 或 `rig_id`。
- `calibration.json`：本机标定副本，可脱离最初保存路径使用。
- `pose_stamps.json`：按 SHA256 编号保存本机标定、相机到标定板的完整 4×4 变换、相机中心、IR1 基准流和固定机位使用条件。旋转与平移同时保存。
- `frames.jsonl`：每个 IR1/IR2/RGB 视频帧记录原有设备/主机时间戳、视频索引、`pose_stamp_id`、IR1 相机中心和 `pose_valid`。RGB/IR2 通过 session 中的设备外参关联到 IR1。
- `imu.csv` / `summary.json`：保留 IMU 与首次机位运动报警时间。报警后的固定外参失效，原始音视频继续保存。

标定板坐标原点沿用现有模型定义，未对旧标定坐标做隐式重置。新标定同时保存冻结参考帧的时间信息。已经开始的录像使用不可变副本；修改界面中的标定不会改写历史录像。用户需要保持完整 session，不能只转发 AVI 丢弃位姿和时间关联。

## 汇总与兼容

三机合成不再检查三段录像是否预先绑定同一个 rig ID，而是检查三个不同序列号和角色、源 session 与本机结果是否一致、帧引用的位姿是否存在，以及模型尺寸、坐标、矩阵、误差等原有数值条件。对相同位姿组合只结算一次，按帧记录对应 `rig_id` 和三个 `pose_stamp_ids`。

合成输出 `rig_calibrations.json` 以及原有视频、音轨、点云与轨迹；只有一组位姿时另存 `rig_calibration.json`。自动录后结算使用独立 schema，明确固定标定板假设，不将它写成操作员已经人工核对机位布局。原有手动结算工具可选保留，旧的预结算录像和单一位姿旧版人工后处理仍能使用。

采集端当前使用已标定固定机位，不做移动机位的持续视觉位姿估计。合成支持不同帧引用不同已保存的有效位姿；没有有效位姿的帧不能靠 IMU 自动补出平移。

## 检查

`check_deferred_capture_v8_2.py` 覆盖实际 Qt 点击：只完成本机标定且没有 rig 时允许录像；后台接受本机标定；错误相机或未通过的诊断结果拒绝；标定快照不可变；各路逐帧绑定位姿与时间；运动报警有效性；位姿文件不一致拒绝；录后结算不伪造人工确认。

`check_reconstruction_v6.py` 改为三份都没有预结算文件的 session，验证重建与融合；其中一段的后半部分引用另一份已保存的位姿，检查融合后的三维位置确实跟随每帧位姿改变，并保存两组结算结果。旧版人工处理也用无预结算录像检查。
